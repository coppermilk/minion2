# Инструкция для браузерного агента: подключить NAS к разделу «Версии» сайта

NAS обновляет minion2 не скриптом из этого репозитория, а отдельным инструментом **nas-update**
(`/volume1/docker/nas-update/`, задача DSM `nas-update` каждые 5 минут, репозиторий github.com/coppermilk/nas-update).
Отчёт о версии шлёт сам nas-update, когда в его конфиге приложения есть раздел `[report]`. Делается через DSM в браузере.
Ничего не удалять, контейнеры руками не трогать; если шаг не получается — остановиться и написать, что увидел.

Нужно заранее от Тёмы: значение ключа сайта `BOARD_KEY` (в чате не называть). Коммит nas-update с отчётом уже в `main`:
`d5ebdc68a3072fb446d91155f4460d7ccd2b7b0a` — его и закрепить.

## 1. Обновить nas-update до коммита с отчётом

1. Панель управления → Планировщик задач → задача «nas-update install» (выключенная, запускается руками) → Редактировать →
   «Настройки задачи» → в поле «Выполнить команду» найти строку `C=…` и заменить sha на
   `d5ebdc68a3072fb446d91155f4460d7ccd2b7b0a`. ОК.
2. Выбрать «nas-update install» → «Выполнить» → подтвердить. В результате задачи (Действие → Просмотр результата) должен быть
   новый sha и строки dry-run без ошибок.

## 2. Ключ сайта в файл только для root

1. File Station → `docker/nas-update/` → создать папку `secrets` (если нет).
2. В ней создать файл `versions.key` (Text Editor → Создать; кодировку выставить UTF-8), содержимое — только ключ, одной строкой,
   без кавычек и пробелов. Сохранить.
3. Свойства файла и папки `secrets` → владелец `root`, права: только владельцу чтение и запись (остальным ничего).

## 3. Раздел [report] в конфиге приложения

File Station → `docker/nas-update/apps/minion2.conf` → открыть в Text Editor (кодировка UTF-8) → в конец добавить:

```
[report]
url             = https://daetotyoma.com/admin/versions/minion2-nas
key_file        = /volume1/docker/nas-update/secrets/versions.key
heartbeat_hours = 24
```

Сохранить. Если файл называется иначе (имя файла = имя приложения), добавить в тот, где `project = minion2`.

## 4. Проверить

1. Планировщик задач → задача `nas-update` → «Выполнить» один раз (или подождать 5 минут). В её результате должна быть
   строка «отчёт о версии: heartbeat → сайт принял» (или «deploy → сайт принял», если как раз было обновление).
   Если «сайт отверг … (401)» — рядом сайт пишет причину: «не задан секрет BOARD_KEY» — секрета нет в Cloudflare → Workers &
   Pages → проект сайта → Settings → Variables and Secrets → Production (добавить `BOARD_KEY` со значением ключа и сделать
   Deployments → Retry deployment; это делает Тёма); «ключ не совпал» — в `versions.key` другое значение (сверить, без пробелов и
   переносов). Проверить ключ без NAS: открыть в приватном окне `https://daetotyoma.com/admin/dashboard/?key=<ключ>` — доска
   открылась, значит ключ верный. «key_file не прочитан» — неверный путь или права файла.
2. Открыть `https://daetotyoma.com/admin/versions/` под паролем админки: карточка «minion2 на NAS» показывает коммит, «жив»
   с сегодняшним временем и «в порядке».
3. Написать Тёме, что показывает страница «Версии» и что было в результате задачи.
