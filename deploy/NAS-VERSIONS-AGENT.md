# Инструкция для браузерного агента: подключить NAS к разделу «Версии» сайта

Цель: NAS сам сообщает сайту (`https://daetotyoma.com/admin/versions/`), какая версия minion2 на нём стоит, прошло ли обновление
или откатилось, и раз в день подтверждает, что жив. Делается через DSM в браузере, без SSH. Ничего не удалять, контейнеры руками
не трогать. Если какой-то шаг не получается — остановиться и написать, что увидел.

Нужно заранее от Тёмы: значение `BOARD_KEY` (ключ доски команды сайта; хранится у Тёмы, в чате его не называть). Если ключ
потерян, Тёма задаёт новый в Cloudflare Pages (переменная `BOARD_KEY` проекта сайта) и даёт его агенту.

## 1. Найти скрипт обновления

1. Войти в DSM → Панель управления → Планировщик задач.
2. Найти задачу «minion2 - update on NAS» → Редактировать → вкладка «Настройки задачи» → поле «Выполнить команду».
3. Записать путь скрипта из команды (например `sh /volume1/docker/.../update.sh`). Дальше он называется «скрипт обновления».
   Если путь — `/volume1/docker/minion2/deploy/nas-update.sh`, то скрипт обновляется вместе с репозиторием и шаги 4 уже сделаны в
   репозитории: пропустить раздел 4.

## 2. Получить новые файлы репозитория

1. В Планировщике задач выбрать «minion2 - update on NAS» → «Выполнить» → подтвердить. Задача сама забирает `origin/main`
   и перезапускает контейнеры тем же образом (это обычное обновление, 2–4 минуты).
2. Дождаться письма/результата задачи: в конце должно быть «все контейнеры живы». Если «откатываюсь» — остановиться и сообщить.
3. File Station → `docker/minion2/deploy/` — убедиться, что появился файл `report-version.sh`.

## 3. Ключ в .env

1. File Station → `docker/minion2/.env` → правой кнопкой → «Открыть с помощью Text Editor» (пакет Text Editor должен быть
   установлен; если нет — Центр пакетов → установить «Text Editor»).
2. В конец файла добавить строку `VERSIONS_KEY=` и после `=` вставить ключ от Тёмы, без кавычек и пробелов. Сохранить.
3. Файл `.env` никуда не копировать и не показывать.

## 4. Три строки в скрипт обновления (только если скрипт не из репозитория)

Открыть скрипт обновления в Text Editor и добавить вызовы отчёта. Путь к `report-version.sh` — рядом с репозиторием:
`/volume1/docker/minion2/deploy/report-version.sh` (если репозиторий лежит в другом месте, подставить его).

1. После удачного обновления — там, где скрипт пишет «все контейнеры живы» и обновление считается успешным (не в ветке
   отката), добавить строку:
   `sh /volume1/docker/minion2/deploy/report-version.sh deploy 1 "обновлено, все контейнеры живы" || true`
2. После отката — там, где пишется «откат удался — работает прежняя версия», добавить:
   `sh /volume1/docker/minion2/deploy/report-version.sh rollback 0 "новая версия не поднялась, откат удался" || true`
3. Там, где скрипт отказывается обновлять (дерево коммита не чистое, compose не прошёл политику, нет свежих снапшотов) и
   выходит, перед выходом добавить:
   `sh /volume1/docker/minion2/deploy/report-version.sh error 0 "обновление не запущено: проверка не пройдена" || true`
   Если сообщение проверки уже есть в переменной скрипта, лучше подставить её текст вместо общей фразы.

Сохранить. `|| true` обязательно: отчёт никогда не должен ломать обновление.

## 5. Ежедневный сигнал «жив»

1. Планировщик задач → Создать → Запланированная задача → Пользовательский сценарий.
2. Общие: имя «minion2 - версия на сайт», пользователь `root`, включено.
3. Расписание: ежедневно, время 09:10.
4. Настройки задачи: «Выполнить команду»: `sh /volume1/docker/minion2/deploy/report-version.sh heartbeat`.
   Уведомление по почте можно включить «только при ошибке».
5. ОК → выбрать задачу → «Выполнить» один раз.

## 6. Проверить

1. Открыть `https://daetotyoma.com/admin/versions/` (пароль админки). Карточка «minion2 на NAS» должна показывать коммит,
   «жив» с сегодняшним временем и «в порядке». Если «отчётов ещё не было» — в DSM открыть результат задачи «minion2 - версия на
   сайт» (Планировщик → Действие → Просмотр результата) и прислать текст: там написано, почему не отправилось
   (например «VERSIONS_KEY не задан» или «сайт отверг отчёт (401)» — значит ключ не тот).
2. Написать Тёме: путь скрипта обновления, что добавлено, что показывает страница «Версии».
